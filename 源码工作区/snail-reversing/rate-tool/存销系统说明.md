# 存销系统（服务端数据打包）使用原理说明

> 功能入口：GUI 侧边栏「🗂 存销系统」
> 核心实现：`rate-tool/lib.js` → `genSalesData(engineRoot, opts)`

## 一、这个功能是干什么的

把整个传奇服务端的**核心数据**（怪物爆率、掉落、地图刷怪）解析成**结构化数据包**，按"用户编号"分组，输出到指定目录（如 `D:\存销数据\<服名>\`）。用途：**开新区/换区时直接复用数据**，或把数据交给别人（存销 = 存档+销售）。

## 二、输入参数（GUI 表单 / CLI）

| 参数 | 说明 |
|---|---|
| 生成路径 outDir | 输出根目录（建议 D 盘，如 `D:\存销数据`） |
| 数据目录名 name | 子目录名，默认同服名，**避免有空格**（路径兼容性） |
| 爆率格式 format | `new` = 结构化 JSON / `old` = 原版 MonItems 格式（复制原始爆率文件） |
| 分组数 groupSize | 每组多少条物品数据（默认 100 条/组） |
| 用户编号 userIdType | 数字 / 字母 / 数字+字母——**玩家多时用"数字+字母"防止编号重复** |

## 三、5 个生成阶段（stages）

```
阶段1  物品数据      遍历 MonItems 全部怪物爆率文件 → 解析出 {怪物, 物品, 概率, 数量}
                    → 输出 items/物品数据.json + 按 groupSize 分组 → items/分组/组<编号>.json
阶段2  掉落数据      format=new：爆率数据.json（结构化）
                    format=old：复制原始爆率文件到 drops/MonItems/（保留原版格式，改爆率工具可读）
阶段3  刷新地图数据  解析 MonGen.txt → 刷新地图数据.json（地图/X/Y/怪物/数量/范围/间隔）
阶段4  说明文件      说明.txt（名称/时间/引擎/格式/编号方式/物品条数/组数）
阶段5  完成          "搞定了，可以放心给别人了"
```

## 四、核心算法

### 4.1 物品解析（readMonFile）
真实传奇爆率文件（ANSI/GBK 编码）三种行：
```
1/1<TAB>金币 1000         普通爆率：概率 1/1 + 物品"金币 1000"（数量）
#CHILD 1/22 RANDOM [U3=0]  随机子项头：概率 1/22
1/1<TAB>道士头盔           子项块内的行
```
解析为 `{kind: 'rate'|'child', item, num, rate, count, raw}`，`readMonFile` 返回按原顺序的行结构，`serializeFile` 可原样还原。

### 4.2 分组（groupItems）
`itemsData` 按 `groupSize` 切片 → `[第0组, 第1组, ...]`。每组单独一个文件，方便分发给多个用户。

### 4.3 用户编号（genUserId）
| 类型 | 算法 | 示例 |
|---|---|---|
| 数字 | `index + 1` | 1, 2, 3 ... 100 |
| 字母 | 26 进制（A→Z, AA→AZ...） | A, B ... Z, AA |
| 数字+字母 | `(index/26 取整 + 1) + (index%26 的字母)` | 1A, 1B ... 9Z, 10A |

**为什么分组**：物品数据量可达上万条，一个文件太大；按组给不同玩家编号，组号即玩家编号，避免单文件过大/编号冲突。

## 五、编码处理

- 所有服务端脚本/爆率文件是 **ANSI/GBK**（传奇引擎默认）
- 读取：`decodeBuf(buf)`（iconv-lite GBK 解码，失败回退 UTF-8）
- 写入：`encodeStr(str)`（GBK 编码）
- GUI 便携版/CLI exe 里 iconv-lite 通过 `global.__iconvLite` 注入（bundle 内联加载器）

## 六、常见问题

- **输出路径含空格**：数据目录名不要有空格（如 `毕业端 2` → `毕业端2`）
- **爆率格式选 new 还是 old**：`new` 输出结构化 JSON（给程序读）；`old` 保留原版爆率文件（给引擎/人读，改爆率工具可直接操作）
- **分组大小**：默认 100 条/组；物品多时可调大（如 500），组少更好管理
- **生成失败**：检查引擎根目录是否正确（需含 `Mir200\Envir\MonItems` 和 `MonGen.txt`）

## 七、CLI 用法

```
rate-tool sales <引擎根> --out <输出目录> --name <目录名> [--format new|old] [--group 100] [--uid 数字|字母|数字+字母]
```
