# 存销系统：代码逻辑 + 使用教学 + 与虾米区别

> 2026-08 整理。实现位于 `rate-tool/lib.js`（genStoreScript / genSalesData / storeCleanScripts / storeTimerId），GUI 面板「存销系统」。

## 一、一句话定位

存销系统 = **把服务端爆率/物品/地图数据打包成"能直接卖给新服的完整数据包"**（genSalesData）+ **在服务端注入一套"玩家背包存储"脚本**（genStoreScript，玩家掉落的物品按配置自动存入"通区文件"仓库，多区共享）。

## 二、两大功能 + 两个工具

| 函数 | 类型 | 干什么 |
|---|---|---|
| `genStoreScript` | 商店脚本生成 | 往服务端 QuestDiary/QManage/QFunction 注入「背包存储」脚本（咕咕鸡模板） |
| `genSalesData` | 存销数据打包 | 把 MonItems/地图/刷怪导出成 `items/分组 + drops + 刷新地图数据 + 说明.txt` |
| `storeCleanScripts` | 清理 | 剥掉 QManage/QF 的注入标记块 + 删除功能目录（还原） |
| `storeTimerId` | 辅助 | 全 Envir 扫描 `SETONTIMER` 占用，返回未用定时器 id（复用旧标记块 id） |

## 三、genStoreScript 代码逻辑（对齐虾米 1.3.6 `_StoreGeneratorLite`）

参数：功能文件夹 / 脚本名 / 方法名 / 分类目录 / 通区目录 / 区服文件夹 / **U 变量（固定 U335）** / 间隔(秒) / QR 序号(默认 200) / 资源编号 / 掉落检测方法名(默认 掉落前检测)。

**① 模板替换 `applyRepl`**（核心）
- 模板 = `rate-tool/store-template.txt`（咕咕鸡通区存储模板，34KB）
- 用占位符 `\u0000YGE\u0000` 隔离功能性锚点（`.txt` / `@` / `[@]`），再替换裸词，**避免 scriptName 含「咕咕鸡过滤」时二次替换成 `_Test_Test`**
- 替换项：`游戏功能→功能文件夹`、`..\..\..\..\通区文件\→实际通区`、`<$SERVERNAME>→区服文件夹`、`<$USERID>_<$USERNAME>→<$STR(U335)>`（编号槽）、`QuestDiary\咕咕鸡物品分类→分类目录`、`SETONTIMER 51→{timerId}` + 间隔一并替换

**② 生成 4 个脚本**（QuestDiary\<功能文件夹>\）
1. `创建文件.txt`：首次登录建通区目录/用户 ini（`ForceDirectories` + `CreateFile`）
2. `界面配置读取.txt`：22 个分类文件（宝石/斗笠/盾牌…所有物品.txt）`GetTextLineCount` 读行数 → 配置背包存储各栏位
3. `存销变量初始化.txt`：**U335 编号分配 1000-9999**（防重复：`U变量防重复.txt` 记录已用编号，满了报错）
4. `主脚本（脚本名.txt）`：咕咕鸡模板替换产物（商店主界面 + 存储逻辑）

**③ QManage 注入**（写前 `.store-bak` 备份，清旧标记）
- `[@Login]` 段后插入：`#CALL 存销变量初始化` → 设 S$用户数据存储地址/物品数据/地图数据 → `#CALL 界面配置读取` → **`ADDBUTTON <资源编号> 200 10 11 12 10 92 1 -1`**（挂主界面按钮）→ 新玩家 `#CALL 创建文件`
- 文件尾部追加定时器块：`[@OnTimer{id}]`（**无空格**）+ 读 `背包存储定时` 配置 → 开则 `#CALL 主脚本 @开启背包存储`，关则 **`SetOffTimer {id}`**

**④ QFunction-0.txt 注入**（写前备份 + **注入前扫描段名/按钮号冲突**）
- `[@掉落前检测]`：掉落时读用户 ini 的过滤/存储配置 → 过滤物品 `StopDropItem`，存储物品写入仓库索引/数量文件
- `[@ButtonClick200]`：主界面按钮回调 → `#CALL 主脚本 @购买`

**⑤ storeTimerId**：正则收集全部 `SETONTIMER n` → 优先复用旧标记块 id → 否则 51→52-255→1-50

## 四、genSalesData 代码逻辑（存销数据打包，5 阶段）

| 阶段 | 输出 | 内容 |
|---|---|---|
| 1 物品 | `items/物品数据.json` + `items/分组/组{编号}.json` | 全怪掉落展开（怪/物品/rate/count），按 `groupSize`（默认 100）分组，`genUserId` 生成编号（数字/字母/数字+字母） |
| 2 掉落 | `drops/MonItems/*.txt`（新格式）或原样复制（原版） | **新爆率格式** = 按 `#CHILD 1/N RANDOM` 分组结构（组头保分母、组内 1/1 归一、已有组透传）——游戏内可直接用的分组爆率 |
| 3 地图 | `刷新地图数据.json` | MonGen 全部刷怪行（地图/怪/数量/间隔） |
| 4 说明 | `说明.txt` | 数据包名/时间/引擎/爆率格式/编号/条数（单次写入，真实键名） |

## 五、使用教学

### GUI（推荐）
1. **存销数据打包**：面板「存销系统」→ 生成路径（如 `D:\存销数据`）→ 数据目录名（同服名，无空格）→ 爆率格式（新爆率 = #CHILD 分组 / 原版 = 复制原文件）→ 分组数（玩家多调大）→ 用户编号（玩家多选**数字+字母**防重复）→ 生成
2. **商店脚本生成**：面板「🏪 商店脚本生成」→ 功能文件夹/脚本名/方法名/分类目录 → 通区目录/区服名称（默认 `<$SERVERNAME>`：多区共享通区时自动取本区区名；单区可填实际区名如「一区」更直观）→ U 变量 U335 → 间隔 60 → QR 200 → 资源编号 0 → 生成
   - 生成后 QManage/QF 自动注入，**重启 M2 生效**
3. **清理**：🧹 清理存销（剥标记块 + 删功能目录，`QManage.txt.clean-bak` 备份）
4. **定时器**：⏱ 选定时器（看已占用 + 推荐未用）

### CLI
```
rate-tool store-gen <引擎根> --folder 商店功能 --script 商店 --method 购买 --common 通区文件 --zone 一区 --interval 60 --btn 200
rate-tool store-clean <引擎根> --folder 商店功能
```

### 部署后游戏内流程（数据流）
玩家登录 → QManage [@Login] 初始化 U335 编号（1000-9999 防重复）+ 建用户 ini → 挂 ADDBUTTON 按钮 → 打怪掉落 → QF 掉落前检测读配置：过滤物品直接不落、存储物品写仓库 → 玩家点按钮打开商店界面（主脚本）→ 配置背包存储定时 → 定时器到点自动存储 → 物品/地图数据（genSalesData 打包）供多区复制部署。

## 六、与虾米存销的区别

> 前提：**1.4.3 存销源码已定位**：`C:\Users\Administrator\Documents\Codex\2026-08-10\d-v1-3-6\outputs\虾米工具箱V1.4.3_持续恢复包\_fragments\main_carchive\source_fragments`（1976-1985 StoreGenerateWorker/DeleteWorker/SettingsPage、1817/1818/1819 本地模板渲染 7 产物、1843/1845/1848 清理/删产物/定时器查找；`assembled\工具箱_qt_recovered.py` 967KB 组装版）。1.4.3 核心仍是 `_StoreGeneratorLite`（改用 `run_complete_transaction` 事务化）。我们的实现对齐 1.3.6 `_StoreGeneratorLite`（fragments_best 恢复齐全）。

- 定时器 id 复用旧标记块（虾米 1132）

- 22 分类 GetTextLineCount、U335 1000-9999 分配
