# 引擎识别 + 服务端健检 —— 三家实现专题

> 引擎识别 = 从 M2Server.exe 判断引擎类型（GEE/GOM/LF/996 等）。
> 服务端健检 = 检查 !setup.txt 目录键是否存在、端口是否一致等开区常见坑。

---

## 一、功能是什么

- **引擎识别**：不同引擎（GEE/GEEM2/GOM/翎风LF/996）的菜单结构、配置格式有差异，工具需先识别引擎再适配。
  - 常见特征串（读 M2Server.exe 字节流）：`GEEPAK3 / GEEPAK2 / GEEM2LP / GEEM2 / GAMEOFMIR2 / GAMEOFMIR / D3DM2 / MIRYQ / ssNGom / 996M2 / BLUEM2`
  - 翎风（LF）新引擎 M2Server.exe 无特征串（可能加壳）→ 兜底 FileVersion 判断
- **健检**：!setup.txt 目录键（BaseDir/BoxsDir/CastleDir/ChatDir/ConLogDir/LogDir/GuildDir/NoticeDir）存在性 + DB 端口一致性（!setup DBPort vs DBServer ServerPort）

## 二、三家实现对比

| 实现 | 机制 | 状态 |
|---|---|---|
| **虾米** | 读 M2Server.exe 搜特征串（if-elif 链：`GEEPAK3→GEEPAK2→GEEM2→...→GAMEOFMIR→D3DM2→MIRYQ`） | 最直接，元歌已吸收 |
| **蜗牛** | 引擎控制支持 **LF/GOM/NGOM/996/ssNGom**（M2Config* 配置对象分引擎适配） | 按引擎适配配置 |
| **快捷助手** | "引擎："下拉（用户手动选引擎）+ "显示M2窗口标题" | 手动选择 |

## 三、元歌工具箱实现

**函数**（rate-tool/lib.js）：
- `detectEngine(engineRoot)`：读 `Mir200\M2Server.exe` 字节流搜特征串（11 个引擎特征）→ 未匹配返回"可能翎风/LF 系" + FileVersion 兜底
- `checkServerConfig(engineRoot)`：8 个目录键存在性 + DB 端口一致性 → 返回检查项列表 + 问题列表

**CLI**：
```
元歌工具箱-CLI.exe engineck <根>
# 输出：引擎识别 + 目录键检查 + DB端口一致性 + 问题清单
```

**GUI**：引擎健检面板（🔍）——运行检查 → 显示检查项结果 + 问题（面板内 + 操作日志双写）。

**真实端实测**（翎风01）：
- 引擎识别：未知引擎（可能为翎风/LF 系）——翎风 M2Server.exe 无 GEE/GOM 特征串
- **健检抓到真实配置错误**：`目录键 ChatDir 不存在: D:\战火王者之风\Mir200\ChatLog\`（旧路径残留，实际应为 `D:\cqzs\...\Mir200\ChatLog\`）
