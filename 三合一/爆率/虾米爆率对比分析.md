# 虾米爆率管理 vs 元歌爆率调整 —— 对比分析与融合方案

> 来源：虾米 `工具箱_qt.py`（main-structure.txt 结构级还原，5 个 Worker 类）vs 元歌 `rate-tool/lib.js` 爆率模块

## 一、虾米爆率管理的完整逻辑

### 1. 功能总览（爆率设置页 dropRatePage）
| 功能 | Worker 类 | 参数 | 备份 |
|---|---|---|---|
| 新增爆率 | `_MonItemsAddWorker` | root_dir, items(列表), rate | 新增爆率备份 |
| 整体爆率优化 | `_DropOverallOptimizeWorker` | root_dir, method, maps_text, monsters_text, items_text, range_mode, range_value, op, op_value | 整体爆率优化备份 |
| 二级爆率优化 | `_DropOptimizeWorker` | root_path | 二级爆率优化备份 |
| #CALL 还原 | `_CallRestoreBackupWorker` / `_DropOptimizeWorker` | root_path | #CALL还原备份 |
| 普通爆率分组 | `_DropGroupingWorker` | root_dir, group_size | 普通爆率分组备份 |
| 指定删除 | `_DropSpecificDeleteWorker` | root_dir, delete_content | 指定删除备份 |

### 2. 整体优化的核心流程（_DropOverallOptimizeWorker.run）
```
1. 选目标（method）：
   - 按地图：_load_mapinfo(双向映射 code↔name, 去尾部数字) → _maps_to_codes(地图名→代码)
            → _monsters_from_mongen(从 MonGen.txt 按地图代码取怪, 跳过 ; #)
            → _pick_monster_files(怪名→MonItems/*.txt, 去空白)
   - 按怪物：直接 monsters_text → _pick_monster_files
   - 按物品：items_text
2. 读文件：_read_lines_best_effort —— gb18030/utf-8-sig/gbk/big5/utf-8 多编码容错（replace 兜底）
3. 逐条处理：
   - _normalize_item_name（物品名规范化：去 BOM/全角空格/NBSP/制表符/注释///(?i)\s+random.*$/RANDOM 后缀）
   - _match_range(den)：range_mode 大于/小于/等于 + range_value（按爆率分母范围筛）
   - _apply_op(den, op, val)：加/减/乘/除/=（'除数不能为 0' 保护）
4. #CALL 处理：_drop_resolve_call（路径校验：防设备/扩展路径/目录穿越、禁止指向备份或事务目录）
            → _drop_check_call_target（#CALL 目标必须是 TXT）
5. 写回：_drop_encode_text（保留原编码 auto/raw/meta）
6. 排除：_drop_is_private_path（跳过 备份/backup/.xiami- 目录）
```

### 3. 其他功能
- **新增爆率**：把 items 列表 + rate **追加到全服所有 MonItems 文件**（"新增物品爆率（MonItems 全怪物）"）
- **二级优化**：`_optimize_content` 优化已有 #CHILD 嵌套结构（合并/整理）
- **分组**：按 group_size 把普通爆率分组成 #CHILD 随机组
- **指定删除**：按 delete_content 匹配删除
- **全部操作自动备份 + 可还原**（_DropFolderRestoreWorker/_CallRestoreBackupWorker，备份目录被 _drop_is_private_path 保护）

## 二、元歌当前爆率调整（lib.js）

| 功能 | 实现 | 操作单位 |
|---|---|---|
| 单怪加/删物品 | addRate/delRate（append/删除模式） | 单怪 |
| 全服加/删 | globalOp（遍历所有 MonItems 文件） | 全服 |
| 随机转换 | convertRandomFile（普通爆率→#CHILD RANDOM 组） | 单怪 |
| 随机爆率 | randRate（概率随机） | 单怪 |
| 重复检测/删除 | findDupRates/delDupRates | 全服 |

| 备份 | quickBackup（手动备份 MonItems） | 手动 |

## 三、差距对照

| 维度 | 虾米 | 元歌 | 差距 |
|---|---|---|---|
| 目标筛选 | method：按地图/按怪物/按物品 | 全服固定 | ❌ 大——虾米可精确圈定目标 |
| 范围匹配 | den 大于/小于/等于 筛 | 无 | ❌ 缺失 |
| 运算类型 | 加/减/乘/除/= | 只有 ×倍数 | ❌ 缺加减除/设定 |
| 操作单位 | den（概率分母 1/x） | rate（百分比） | ⚠️ 需换算（den=100/rate） |
| 新增爆率 | 多物品批量全怪 | 单物品 | ⚠️ 半支持 |
| 备份还原 | 每操作自动备份+还原列表 | 手动单次备份 | ❌ 缺失 |
| #CALL 还原 | 解析还原 + 防穿越 | 无 | ❌ 缺失 |
| 二级优化 | 优化 #CHILD 结构 | 只有转换 | ⚠️ 缺优化 |
| 分组 | group_size 分组 | 无 | ❌ 缺失 |
| 指定删除 | 任意内容删除 | 仅重复删除 | ⚠️ 半支持 |
| 编码 | 多编码自动检测 | GBK 固定 | ⚠️ 可增强 |
| 物品名规范化 | 去 RANDOM/空白/BOM/注释 | 无 | ❌ 缺失 |
| 排除备份目录 | 自动跳过备份文件 | 无 | ❌ 缺失 |

## 四、融合方案（按价值排序）

### P0 高价值（补功能）
1. **整体优化升级**（globalOp → overallOptimize）：
   - 加 `method`（all/map/monster/item）+ 目标列表
   - 加 `rangeOp`（大于/小于/等于）+ `rangeValue`（按 den 筛）
   - 加 `op`（add/sub/mul/div/set）+ `opValue`
   - den 与 rate 双向换算（内部统一用 den 操作，显示 rate）
2. **操作前自动备份 + 还原列表**：所有爆率写操作先备份到 `MonItems\@backup\时间戳\`，GUI 加"还原"下拉；处理时跳过备份目录

### P1 中价值（补能力）
3. **物品名规范化**：`normalizeItemName`（去 BOM/全角空格/NBSP/制表符/`//`注释/`(?i)\s+random.*$`）——所有爆率读入时应用
4. **#CALL 还原**：解析 `#CALL` 引用的爆率文件，展开成内联或校验目标（防目录穿越/防指向备份）
5. **新增爆率批量**：addRate 支持 items 数组（一次加多个物品到全服/指定怪）
6. **多编码检测**：读文件时 gb18030→utf-8-sig→gbk→big5 依次尝试

### P2 低价值（可选）
7. **普通爆率分组**：按 group_size 把散落普通爆率合并成 #CHILD 组
8. **指定删除增强**：delRate 支持按 内容片段/怪名/物品名 多条件匹配
9. **二级优化**：对已有 #CHILD 结构做合并整理

## 五、实施顺序建议
1. 先做 P0-1（整体优化升级：筛选+范围+运算）—— 工作量中等，价值最高
2. 再 P0-2（自动备份+还原）—— 安全兜底，所有写操作受益
3. P1 按需逐个补
